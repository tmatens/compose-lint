# CL-0027: Bounded-grant capabilities (SYS_PTRACE, PERFMON, SYS_TIME, DAC_READ_SEARCH)

**Severity:** MEDIUM

**Derivation** (see [severity model](../severity.md)):

- **Baseline:** A — the attacker already has code execution in this container, as the workload uid
- **Precondition:** Technique — each member is a primitive that needs a published technique to convert into impact, not a supported call that realises it
- **Impact:** Single container — the reach is this container's own processes, a kernel read, or (for `SYS_TIME`) host integrity short of any takeover
- **Qualifier/modifier:** none
- **Derived:** Technique × Single container = HIGH
- **Shipped:** MEDIUM — override `detection-precision` — the rule cannot tell a debugger sidecar or an NTP client, which need these capabilities to work, from a workload that has no business holding them ([ADR-020](../adr/020-severity-scoping-and-overrides.md))
- **Evidence:** `_cl0011` in `scripts/validate_rule_premises.py` — `cap_add` grants the named capability. `SYS_TIME`'s host-global clock is separately confirmed by `_t_sys_time`, which sets the clock inside a container and reads the change back

## What it detects

`cap_add` entries whose grant is real but bounded:

| Capability | Grants | Why it is not higher |
|---|---|---|
| `SYS_PTRACE` | trace and read other processes' memory | confined to this container's own PID namespace unless `pid: host` is also set, which [CL-0010](CL-0010.md) flags |
| `PERFMON` | `perf_event_open` — kernel timing and info disclosure | a read primitive; it discloses, it does not write |
| `SYS_TIME` | set the system clock | host-global (Docker does not isolate `CLOCK_REALTIME`), so it breaks certificate validation, TOTP and Kerberos host-wide — but it is an integrity effect, not a takeover |
| `DAC_READ_SEARCH` | bypass file-read checks; read host files via `open_by_handle_at` | the host-read leg needs a host bind mount to be present, and that mount is flagged by [CL-0013](CL-0013.md) or [CL-0025](CL-0025.md) |

## Why it matters

These weaken isolation without opening an escape. That distinction is the whole
point of the tier: before the split they were graded HIGH alongside kernel-module
loading, which made the higher tiers less believable and put a debugger sidecar
in the same bucket as a container escape.

`SYS_TIME` is the one most often underestimated. The clock is **host-global** —
a container holding this capability moves the host's wall clock, and every
workload on the machine sees it. Certificate validation, time-based one-time
passwords and Kerberos all break together, and the failure looks like an outage
rather than an attack.

## Fix

Remove the capability unless the workload demonstrably needs it:

```yaml
# Before
services:
  profiler:
    image: myprofiler:1.0
    cap_add:
      - SYS_PTRACE

# After — if the sidecar genuinely profiles a neighbour, scope it explicitly
services:
  profiler:
    image: myprofiler:1.0
    cap_drop:
      - ALL
    cap_add:
      - SYS_PTRACE
    pid: "service:app"     # not pid: host — see CL-0010
```

## When to suppress

These are the capabilities with the most legitimate uses in the set, so
suppression here is ordinary rather than exceptional:

- `SYS_TIME` — an NTP client (chrony, ntpd) running in a container. Prefer
  syncing the clock on the *host* and letting containers inherit it; a container
  that sets the host clock is a design smell even when it works.
- `SYS_PTRACE` / `PERFMON` — debugger, profiler and APM sidecars. Scope them to
  the container they inspect with `pid: "service:<name>"` rather than `pid: host`.

Suppress per service with a `reason:` naming the workload.
