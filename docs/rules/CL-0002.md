# CL-0002: privileged: true — what it grants and how to replace it

**Severity:** CRITICAL ([how it is derived](#severity-derivation))

`privileged: true` hands the container every capability and every host device,
and turns off its seccomp and AppArmor profiles, so escaping to host root is a
one-liner. Remove it and grant only the specific thing the service needed.

## Fix

```yaml
# Instead of:
privileged: true

# Use:
cap_drop:
  - ALL
cap_add:
  - NET_ADMIN      # only what you actually need
security_opt:
  - no-new-privileges:true
```

1. **Find out what it was for.** Remove the line, start the service, and read
   the logs; the [CL-0006](CL-0006.md#fix) drop-and-observe loop names each
   capability a failure points at. Most uses are one of these, and each has a
   narrower setting:

   | Use case | Instead of `privileged: true` |
   |---------|---------------------|
   | Mount filesystems | Mount on the host and hand the container the result. `cap_add: SYS_ADMIN` works but is itself CRITICAL ([CL-0024](CL-0024.md#fix)) |
   | Specific device access | `devices: [/dev/foo]` + `device_cgroup_rules` ([CL-0016](CL-0016.md)) |
   | Network configuration | `cap_add: NET_ADMIN` + `cap_add: NET_RAW` ([CL-0011](CL-0011.md#fix)) |
   | Bind a port below 1024 | Nothing: in the container's own network namespace low ports need no capability since Docker 20.10. Only under `network_mode: host` does it take `NET_BIND_SERVICE` ([CL-0006](CL-0006.md#reading-the-failure)) |
   | Run a debugger sidecar | `cap_add: SYS_PTRACE` and `pid: "service:<name>"`, which reaches only that service's processes ([CL-0027](CL-0027.md#fix)) |
   | Docker-in-Docker | Prefer `sysbox-runc` or rootless DinD over `--privileged` |

2. **Recreate the service and check what it holds:**

   ```bash
   docker compose up -d app
   docker inspect --format '{{.HostConfig.Privileged}}' $(docker compose ps -q app)
   # false
   docker compose exec app grep -E 'CapBnd|Seccomp:' /proc/1/status
   # CapBnd:	0000000000001000      (only what you added; decode with capsh)
   # Seccomp:	2                     (0 while privileged: no filter)
   ```

   Privileged, the same container showed `CapBnd: 000001ffffffffff` (every
   capability), `Seccomp: 0`, and 215 entries in `/dev` against 15
   (Docker 29.7.2, `busybox:1.37`).

3. **Check the finding is gone:**

   ```bash
   compose-lint -q compose.yaml | grep CL-0002    # prints nothing once fixed
   ```

## What it detects

Any service with `privileged: true`.

## Why it matters

Privileged mode disables nearly all container isolation. The container receives every Linux capability, every host device under `/dev`, and runs without the default seccomp and AppArmor profiles. PID, mount, and network namespaces are still in place by default, but escape to host root is trivial — `mount`, `unshare`, `mknod`, and BPF are all unblocked, and the host's block devices are all present, so mounting the host root filesystem (`mount /dev/sda1 /mnt`) is a one-liner.

The `release_agent` escape that older write-ups lead with is **cgroup v1 only**. Current hosts run the v2 unified hierarchy, which has no `release_agent` file (verified: `CgroupVersion: 2` on the daemon these rules are grounded against). Do not treat its absence as evidence that a privileged container is contained — the block-device path above needs no cgroup trick at all.

Treat `privileged: true` as **trivially escapable to host root**, not literally equivalent to running on the host — but the practical attack distance is one well-known technique away.

## Severity derivation

**Derivation** (see [severity model](../severity.md)):

- **Baseline:** A — the attacker already has code execution in this container, as the workload uid
- **Precondition:** Direct — the container starts with every capability, every host device, and no default seccomp or AppArmor profile
- **Impact:** Host
- **Qualifier/modifier:** none
- **Derived:** Direct × Host = CRITICAL
- **Shipped:** CRITICAL
- **Evidence:** `_cl0002` — a privileged container holds the full capability set, verified against a live daemon on every CI run
